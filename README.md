# 開発見積ナビ

システム開発の概算費用を、機能をチェックするだけで組み立てるブラウザアプリです。

ヒアリングをしながらその場で使います。相手の要望を聞いて項目にレ点を付けると金額が即座に変わるので、「この機能を入れるといくら増えるか」「予算に収めるなら何を落とすか」を、その場で一緒に見ながら調整できます。持ち帰って計算し直す必要がありません。

## 何ができるか

96項目の機能ツリーから、必要なものにレ点を付けます。金額はチェックのたびに更新されます。依存する項目（例：入力フォームを選ぶとデータ設計とAPI基盤）は自動で追加され、複数の項目から必要とされている間は鍵マークで保持されます。

項目を押すと、追加・削減される金額と、一緒に必要になる作業がその場に出ます。要望と金額のすり合わせは、この増減を見せながら進めます。

## 動作環境

- 実行：Chrome / Edge などの現行ブラウザ
- 配布：静的ファイルを配信できる環境（本番は Vercel）
- 外部ライブラリ・npm install・ビルド：不要
- テスト：Node.js 20 以降

## 起動方法

```powershell
python -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開きます。Pythonがなければ任意の静的HTTPサーバーで構いません。`index.html` を直接開いても基本操作はできますが、保存・読込のブラウザ制限を避けるためHTTPサーバー経由を推奨します。

## 使い方

上から機能ツリーを確認し、必要な項目にレ点を付けます。

- レ点：見積に含める。空欄：含めない
- 上のまとまりを外すと、その下もまとめて外れる
- 依存項目は自動追加され、他の項目から参照されている間は鍵マークで残る
- 鍵マークの横に、保持の原因になっている項目番号を表示
- 項目名は実現したいこと、右側にエンジニア向けの技術名を併記
- 項目を押すと、その単価の「根拠」と「意図」を確認できる

画面上部に合計金額が追従表示されます。下部には選択項目の内訳、依存関係ツリー、明細表が並びます。JSON保存・読込、合計行付きCSV出力、印刷（PDF保存）が使えます。

案件内容は初期状態では端末に保存されません。「この端末に自動保存」を明示的に有効にしたときだけブラウザに保存されます。共有PCではオフのまま使い、引き継ぎには「案件保存」のJSONを使ってください。

## 金額の考え方

```text
概算合計     = 選択された項目（依存項目を含む）の適用単価合計
年間保守目安 = 概算合計 × 10%（別途）
```

同じ依存項目は何度参照されても1回だけ計上します。参考作業時間は期間の目安であり、金額計算には使いません。

- 標準QA一式を選ぶと、単体・結合・画面操作テストは内包扱いで0円
- 外部API連携基盤は単独選択30万円、他機能から自動追加されるときは共通基盤配賦12万円
- 予備費は別枠で一度だけ加算します（現在の設定は0%）

固定単価は DATABANK「価格表 機能別マスタ」（2026年6月29日）の34項目が原本、残る62項目は規模・難易度・再利用性を比較した査定値です。画面とCSVで両者を区別して表示します。

この単価はDATABANK内で比較検討するための相対参考値で、市場相場ではありません。正式見積の前に、対象範囲・既存資料・連携先・確認レベルを確定して校正してください。表示金額は契約金額を保証しません。査定方法と参照した公開資料は [PRICING_RATIONALE.md](PRICING_RATIONALE.md) にあります。

## カタログの拡張

案件固有の項目は画面から追加できます。`catalog.js` を直接編集する場合は、項目番号（`id`）、技術名（`name`）、実現したいことの表示名（`plainName`）、固定単価（`fixedPrice`）、規模（`priceSize`）、参考作業時間（`hours`）、依存項目（`dependencies`）を揃えて更新してください。

代表構成のプリセット定義（`presets`）は画面からは使いません。`tests/engine.test.js` が依存込み金額の固定検証に使うためだけに残しています。

## テスト

```powershell
node --test tests/*.test.js
```

親・中間・末端の解除、共有依存の保持、全96項目の正の単独価格、原本34項目の維持、査定62項目、QA内包、API基盤配賦、代表5構成の金額、画面・CSVの根拠表示、単一ページ構成を検証します。

代表構成の金額を変えたときは、このテストと `PRICING_RATIONALE.md` の表を必ず一致させてください。

```text
app.js                     見積画面の動作
tests/engine.test.js       計算・カタログのテスト
tests/ux-contract.test.js  画面仕様のテスト
HANDOFF.md                 検討の経緯と決定事項
PRICING_RATIONALE.md       単価の査定根拠と参照資料
```
