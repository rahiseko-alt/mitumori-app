# 顧客はアーティファクトを開かない

商談では営業が自分の端末で開き、画面を顧客に見せる。**顧客にリンクは共有しない。**
顧客が外部訪問者として開くと、`db` への書き込みも `sample` の呼び出しもできず、
閲覧専用の抜け殻になるためである。顧客へは商談後に書面を渡す。

権限は3段に分ける。**技術者＝所有者**（すべての level を満たすため、`db` のルールに縛られない）。
**営業＝`interact`**（claude.ai の組織メンバーとして招待する。ヒアリングと見積だけを触れる）。
**顧客＝アクセスなし**。

## Considered Options

- **顧客にもリンクを共有する**: 能力の大半が顧客側で死ぬ。
- **営業をメール招待する**: 手軽だが、メール招待者は `admin` 扱いになる場合があり
  「確定後は改変不可」が崩れる。また、プラットフォームのコメント機能が使えない。

## Consequences

- 確定した見積は `write: "admin"` のパスへ移す。これによりアプリの実装ミスでは破れない形で、
  `interact` の営業が書き換えられなくなる。
- 確定を押すのは営業（商談の場で押せないと意味がない）、取り消せるのは技術者だけ
  （営業に取り消しを許すと「改変不可」が名ばかりになる）。確定の単位は**案件全体**とする。
  項目ごとの確定は「一部確定・一部未確定の見積」を生み、総額が何を指すのか説明できなくなる。
- `sample` は閲覧者自身の Claude アカウントを使い、費用も閲覧者持ちなので、
  **営業ひとりひとりに Claude アカウントが要る**。
- 顧客へ渡すのは**分類10件レベルの小計と総額、および用語表**を載せた書面とし、
  96行の明細は技術者向けの CSV にだけ出す。求められたら明細も出せばよい。
