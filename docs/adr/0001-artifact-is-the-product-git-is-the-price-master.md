# 見積ナビ本体は Claude アーティファクトへ移し、このリポジトリは単価の原本として残す

いまの見積ナビは通信を一切しない静的ページで、商談中にその場で質問を作ることができない。
ヒアリングを製品に入れるには、ページから Claude を呼べる必要がある。Claude アーティファクトの
`sample` 能力がそれを満たし、サーバーも API キーも自前の認証も要らない。よって**動く本体は
アーティファクトへ移す**。

ただしリポジトリは畳まない。96件の見積項目・基準値・依存関係・テスト24件は**git を原本**とし、
アーティファクトはそこから生成した**配布物**として扱う。値上げや項目追加は git で行い、PR で
レビューする。

## Considered Options

- **アプリ内に静的な質問ツリーを埋め込む**: 通信ゼロを保てるが、想定外の答えを掘れない。
  2026-09-03 に473行削除した設問画面と同じ弱点を抱える。
- **アプリからLLMを直接呼ぶ**: サーバー・APIキー・従量課金の管理が増え、このアプリの
  「誰にも依存せず即座に動く」性質を失う。
- **アプリの外で Claude が質問し、結果だけ取り込む**: 今日から動くが、商談中に営業が
  チャット画面を開くことになり、金額が会話に追従しない。

## Consequences

- 印刷と CSV 出力は作り直しになる。
- アーティファクトは案件ごとではなく**1つ**とし、案件は `db` のレコードとして持つ。
  `artifact` 能力が発行できるのは自分自身の新しい版だけで、新しいアーティファクトを
  作ることはできないため、案件ごとに1つにすると案件のたびに技術者の手が要る。
- 単価を誰がいつ変えたかは git の履歴に残り続ける。
