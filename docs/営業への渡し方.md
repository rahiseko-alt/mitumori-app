# 営業への渡し方

営業はスマートフォンの claude.ai から使います。そこからは、このリポジトリのファイルは
見えません。だから**手順と単価を、営業の手元から読める場所に置く**必要があります。

**プロジェクトそのものは共有できません。** claude.ai のプロジェクト共有は Team または
Enterprise プランの機能で、個人プラン（Pro／Max）では自分専用です。そこで、
**プロジェクトは営業ひとりひとりが自分で作り、単価表は Google Drive の共有フォルダから
読ませます。** 単価を変えたとき、Drive の1ファイルを差し替えれば全員に届きます。

## 技術者がやること（1回）

### 1. Drive に共有フォルダを作る

Google Drive に「見積」などのフォルダを作り、次の2つを入れます。

- `見積単価表.md` — 96項目の単価
- `見積論点表.md` — 論点ごとの幅と、聞く順番

どちらも `.claude/skills/mitsumori-flow/` にあります。**ファイル名は変えないでください。**
指示文がこの名前で検索します。

フォルダを営業の Google アカウントへ**閲覧権限**で共有します。編集権限は渡しません。

### 2. 営業に、自分のプロジェクトを作ってもらう

営業が claude.ai で新しいプロジェクトを作り、名前を「見積」などにします。

### 3. 指示を貼ってもらう

`.claude/skills/mitsumori-flow/project-instructions.md` の、**先頭のコメント行より
下をすべて**コピーして、プロジェクト設定の「指示」欄に貼ります。技術者が本文を
そのまま渡してかまいません。

### 4. Drive をつないでもらう

営業の Claude アカウントで、Google Drive の接続を有効にします。共有したフォルダが
見えることを、Drive 側で確かめてもらってください。

### 5. 動くことを確かめる

プロジェクトの中で、適当な商談メモを1つ貼ってみてください。

> 山陽建設さん。現場の写真を職人がスマホで撮って、事務所が確認する。いまはLINEで送って
> きて事務所が手で台帳に貼っている。月300件くらい。協力会社も10社くらい使う。トンネル内は
> 電波が入らない。所長が承認してから施主に提出。写真は工事ごとにまとめてPDFで出したい。
> 会計とはつながなくていい。

まず**「単価表（価格基準日 2026-06-29）を読みました」のような一言**が出るはずです。
これが出なければ Drive を読めていません。そのまま金額が出てきたら、**指示の貼り漏れです。**
読めていないのに推測で金額を作っている状態なので、すぐ止めてください。

続いて「こういう製品で合っていますか」と幅つきの金額、そして**顧客に読み上げる質問が3つ、
ボタンで選べる形で**返ってくれば正しく動いています。

選択肢が文章で並んでいて打ち込みを求められたら、その環境ではボタンの機能が使えて
いません。動きはしますが、営業は片手で操作しているので、そのままでは実用になりません。

**未決の一覧だけを返して「次回これを伺ってください」で終わったら、失敗です。** 指示の
貼り漏れを疑ってください。聞くのは Claude の仕事で、聞く場は商談の最中です。営業に
宿題を出すためのものではありません。

## 営業がやること

### 商談の前

準備は要りません。プロジェクトを開けば始められます。

### 商談の中

**1. 聞く。** いつもどおり顧客の話を聞きます。この間、Claude は使いません。

**2. 要望を渡す。** 形は何でもかまいません。議事録でも、音声入力で吹き込んだ話し言葉でも、
箇条書きでも、顧客からのメールの転記でも、「現場の写真を共有したいらしい」の一行でも
かまいません。**「まとめて」と書く必要もありません。** 渡せばそのまま始まります。

途中で止めたいときだけ「まだ途中」と書いてください。次の分を待ちます。

**3. 読み上げる。** 「こういう製品で合っていますか」と、いまの金額と、**質問が3つ**
返ってきます。質問はそのまま顧客に読み上げられる文になっています。言い換えなくて
かまいません。

**4. ボタンを押す。** 選択肢がボタンで出ます。顧客の返事に合うものを押すだけです。
打ち込む必要はありません。答えられないものは「分からない」を押してください。それも
正しい答えで、決まっていないものとして残ります。

**5. 金額が動く。** 「いまの決定で◯◯〜◯◯千円になりました。上限が◯◯千円下がりました」と
返り、**次の3問**が出ます。これを繰り返します。顧客は金額が縮んでいくのを見ることに
なります。それが答え続ける理由になります。

**6. 途中で止めてよい。** 「今日はここまで」と書けば止まります。次の商談で、残った論点の
続きから再開します。仕様書が要るときは「まとめて」と書くと文書になります。

金額には幅があります。**真ん中の金額を言ってはいけません。** 真ん中に根拠はありません。
「まだ決まっていないことが◯件あるので、この幅です。決まるたびに上限が下がります」と
伝えてください。

### 商談のあと

技術者へは、チャットの内容をそのまま渡してください。整理しなおす必要はありません。

## 営業が守ること

- **価格表にない金額を顧客に言わない。** Claude が「価格表にない項目です」と返したら、
  その場で金額を答えず「持ち帰って確認します」と言ってください。
- **幅を勝手に狭めない。** 「もう少し安くなりませんか」と言われても、決まっていない論点が
  残っている限り幅は縮みません。縮めるには論点を決めるしかありません。これは値引きの話
  ではなく、まだ何を作るか決まっていないという話です。
- **確定は顧客が承認してから。** 確定すると金額は動かせなくなります。取り消せるのは
  技術者だけです。
- **ここは作る場所ではありません。** 「こういうアプリを作って」と入れても、作らずに
  見積が返ってきます。それが正しい動きです。動くものが出るのは、仕様が固まったあとの
  デモだけです。

## 単価を変えたとき（技術者）

`catalog.js` を直したら、作り直して **Drive の2ファイルを差し替えます。**

```
node scripts/build-price-table.js
node scripts/build-open-points.js
node scripts/build-project-instructions.js
node --test tests/*.test.js
```

Drive では**同じファイル名で上書き**してください。新しいファイルを足すと、古いほうが
残って、どちらを読むか分からなくなります。

営業に頼むことはありません。Drive を差し替えれば、次の商談から新しい単価で動きます。
**表の先頭に「価格基準日」が入っている**ので、営業の画面に出る一言でどの版を読んだか
分かります。基準日を変えたときは、それが切り替わることを1件で確かめてください。

価格基準日を変えずに単価だけ直すと、営業からは見分けがつきません。単価を動かしたら
`catalog.js` の `priceMasterMeta.createdAt` も更新してください。

## この形の限界

- **音声を丸ごと預かることはできません。** チャットのマイクは1通ぶんの音声入力です。
  1時間の商談を録りっぱなしにする用途には向きません。録音を残したい場合は、端末の
  録音アプリを別に使ってください。
- **Claude が合計を間違える可能性は残ります。** 指示で「項目を並べてから足す」と
  定めていますが、計算そのものを止める仕組みはありません。金額が前回と大きく違うときは、
  営業が並んだ項目を見て気づけるようにしています。
- **項目ごとの明細は顧客に出しません。** 顧客へは分類10件の小計と総額までです。
  求められたときだけ出してください。
- **プロジェクトは営業ごとに別物です。** 指示を直したときは、全員に貼り直してもらう
  必要があります。Drive で配れるのは単価表と論点表だけで、指示文は配れません。
  指示を頻繁に直す段階のうちは、これが手間になります。
- **Drive の接続が切れると止まります。** 金額が出ないという連絡が来たら、まず
  営業側の Drive 接続と、フォルダの共有が生きているかを確かめてください。
  止まるのは正しい動作です。推測で金額を出すよりはるかに安全です。
